# Real Work Systems

## Overview
A portfolio and demo project built by Exequiel to show prospective clients. It should show real-world systems work: clean architecture, reliable automation, and polished results.

**Project:** AI Invoice Processing System. Invoices are uploaded on the dashboard, AI (OpenAI for now) extracts the data, the system checks it (math, duplicates, PO match), a person approves it in Slack, and it gets posted to Xero. A live dashboard shows every invoice and its status.

Gmail intake is NOT built (no Gmail trigger exists). The intake webhook accepts `source=email`, but nothing sends it. Don't describe email intake as working.

## How things work
- Both n8n workflows ("Invoice Processing | 1. Intake + Extraction" and "| 2. Approval + Xero") are generated by `scripts/build_n8n_workflow.py --deploy` (workflow 2 lives in `scripts/approval_workflow.py`, Slack layout in `scripts/slack_blocks.js`). Never edit them by hand in n8n; change the scripts and re-deploy. Deploy copies credentials across nodes by type.
- Tests: `scripts/test_n8n_intake.py --reset` (intake, posts 13 Slack messages), then `scripts/test_approval.py` (signed fake Slack clicks, creates real bills in the Xero demo company). Model test: `scripts/eval_extraction.py`.
- Dashboard (`dashboard/`, Next.js 15 + Tailwind 4): server components read Supabase with the anon key (column grants limit it); `/api/process` forwards samples/uploads to n8n with the webhook secret and enforces demo limits; PDFs render with PDF.js (iframes fail on mobile). Its `.env.local` is generated by `scripts/sync_dashboard_env.py`; sample PDFs are copied into `public/samples` before dev/build.
- Don't touch Exequiel's other n8n workflows (client work).
- README screenshots are regenerated with Playwright (installed in the scratchpad, not the repo) at 1280 wide, 2x scale, then compressed with Pillow.
- Known issue: the AI call takes ~15s from the n8n VPS vs ~3s locally (network path, not the workflow).

## Tech Stack
- **Orchestration:** n8n (Exequiel's existing self-hosted instance)
- **AI extraction:** OpenAI API (PDF input, structured JSON output). Exequiel chose OpenAI to use existing credits instead of paying for Anthropic API. Keep the provider swappable via `AI_PROVIDER`; don't push him to buy Anthropic credits.
- **Database and storage:** Supabase (Postgres + Storage)
- **Dashboard:** Next.js + Tailwind on Vercel
- **Approvals and alerts:** Slack app
- **Accounting:** Xero API (demo company only)
- **Intake:** Gmail and dashboard upload

## Conventions
- Favor clarity and maintainability over clever code.
- Use descriptive names and keep files focused.
- Never commit secrets. Use environment variables and a `.env.example` file.
- Write a short README section for any feature a client might see.
- Never use em dashes in anything written for this project.
- Only use fake sample data and the Xero demo company. No real financial data.
- Export n8n workflows to `n8n/workflows/` after changes so they're versioned.
